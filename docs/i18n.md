# Internationalization

## Sources and build

- `src/locales/en-US.js` and `src/locales/pt-BR.js` contain all interface translations, including errors, dynamic feedback, category names and PDF confirmations.
- `src/i18n.js` provides locale detection, interpolation/plurals, subscriptions, safe preference storage and DOM translation.
- `src/index.html` contains a single shared interface template. `data-i18n` sets text; `data-i18n-aria-label`, `data-i18n-placeholder` and `data-i18n-title` set attributes. The build also fills metadata through `data-i18n-content`.
- `build.mjs` generates the English fallback from the catalogs, embeds both catalogs and all application modules in dependency order, and regenerates CSP hashes.

Both text and PDF work offline through `file://`. Translations are embedded and use text/attribute APIs. Split mixed markup into text spans while retaining structural elements.

## Selection and persistence

A valid manual `safepaste-language` preference wins. Otherwise inspect browser language preferences in order, mapping `pt` variants to `pt-BR` and `en` variants to `en-US`; unsupported languages fall back to English. Automatic selection does not write storage. Explicit PT/EN selection persists even if it matches the already detected locale.

Storage exceptions are caught. With storage disabled, switching still works until the page closes. Browsers vary in `file://` persistence behavior. Only theme/language preferences are stored, never text, PDF bytes, redactions, imported filenames or detector choices.

Update document `lang`, title, metadata, accessible names, placeholders and selected-button `aria-pressed` state. Language buttons retain their native-language names for discoverability.

## Dynamic state

Keep message keys and interpolation values rather than translated strings. `LocalizedError` carries a stable key and optional parameters; errors shown earlier can therefore change language. Unrecognized third-party errors use a safe generic message; PDF invalid/password exceptions have explicit mappings. Do not display exception strings that may embed source content.

`renderText()` is separate from `update()` so language changes do not rerun detection or rewrite textareas. Preserve copy success/fallback feedback, file errors, imported file association, selection, scroll, enabled categories and theme. PDF subscriptions update messages, metadata and removal-button labels without reloading pages, recomputing candidates or resetting review state.

`{name}` interpolates a parameter; count messages use `one` / `other` forms selected through `Intl.PluralRules`, with zero explicitly using `other`. Supply the same placeholders and keys in both catalogs. Missing keys throw during development/tests; missing locale entries fall back to English.

Detector `hit.kind` values and fictional replacements retain legacy spelling for compatibility. `kind.*` catalog entries localize display labels only. CPF/CNPJ/phone/CEP and all other patterns remain identical across languages. UI language does not add US phone/address rules or translate content.

## Validation

```bash
node build.mjs
node --test
npm run test:browser
```

Node tests check selection precedence, persistence, storage failures, plural/interpolation parity, error retranslation, filename localization, embedded catalogs and CSP. The offline browser suites exercise state preservation, imports/downloads, clipboard feedback, text safeguards, reload persistence, mobile layout and export in both languages with the real PDF library. See [test setup](../CONTRIBUTING.md).

Review native browser file pickers and download UI separately: those are controlled by the browser/OS and follow its language settings.
